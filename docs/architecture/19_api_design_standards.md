# 19 — API Design Standards

> Apply `docs/GLOBAL_RULES.md` (esp. R-API-*).

## 1. General
- REST over HTTPS, JSON (UTF-8), base path **`/api/v1`**; OpenAPI 3.1 generated by FastAPI is the contract; published to `frontend/packages/api-client`.
- Resource naming: plural nouns, kebab-case: `/api/v1/products`, `/api/v1/conversations/{id}/messages`, `/api/v1/csv-imports/{id}/confirm`.
- Actions that aren't CRUD: sub-resource verbs via POST: `/conversations/{id}/take-over`, `/subscriptions/{id}/approve`.
- Fields `snake_case`; timestamps ISO-8601 UTC (`2026-10-13T12:00:00Z`); money as `{ "amount": "1250.00", "currency": "BDT" }` (string decimal); IDs UUID strings.

## 2. Areas
| Prefix | Audience | Auth |
|---|---|---|
| `/api/v1/public/*` | anyone (plans, feature matrix, public catalogue, legal) | none, rate-limited |
| `/api/v1/auth/*` | login/register/refresh/logout | mixed |
| `/api/v1/*` (tenant) | seller panel | user + `X-Tenant-Id` |
| `/api/v1/me/*` | user-scope (profile, sessions, user settings, notifications) | user |
| `/api/v1/admin/*` | platform admins | platform role |
| `/api/v1/webhooks/{provider}` | Meta, payment gateways | signature |
| `/api/v1/realtime/stream` | SSE | user |
| `/api/v1/app/config` | clients (min version, flags) | optional |

## 3. Requests
- Validation by Pydantic; unknown fields rejected (`extra="forbid"`) on writes.
- `Idempotency-Key` on POST creating orders, payments, messages, top-ups (stored 24 h in `idempotency_keys`; same key + same body → same response).
- Optimistic concurrency: `If-Match: <version>` (or `version` field) on updates to settings, rules, products → `409 conflict` on mismatch.
- `Accept-Language: bn|en` for localized messages (API returns codes; message text is convenience only).
- Client headers: `X-Client: web|mobile`, `X-App-Version`.

## 4. Responses
- Single resource: the object. Lists:
```json
{ "data": [ ... ], "page": { "next_cursor": "opaque", "has_more": true, "limit": 50 } }
```
- Pagination: cursor-based (`?cursor=&limit=` max 100), filter params explicit (`?status=active&updated_since=`), sorting `?sort=-created_at` (allow-listed fields).
- Errors (all non-2xx):
```json
{ "error": { "code": "catalogue.csv.invalid_header", "message": "Invalid CSV header", "details": {"missing": ["sku"]}, "trace_id": "4bf9…" } }
```
- Status codes: 200, 201 (+Location), 202 (async accepted, returns job resource), 204, 400, 401, 402/403 (entitlement), 403, 404, 409, 422, 429 (+Retry-After), 5xx.
- Long operations (CSV confirm, exports): `202` + `/api/v1/jobs/{id}` polling + realtime event.

## 5. Versioning & evolution
Additive changes in v1 are allowed (new fields/endpoints). Breaking change → `/api/v2` + deprecation headers (`Deprecation`, `Sunset`) ≥ 90 days for mobile clients. OpenAPI diff check in quality gates.

## 6. Security
Auth per R-SEC; CORS allow-list; rate-limit headers (`RateLimit-*`); no sensitive data in URLs; webhooks return `200` quickly after persistence.

## 7. Documentation
Every endpoint: summary, description, tags (= module), permission + entitlement in description, examples, error codes listed. Swagger UI only in non-production (or admin-only).
